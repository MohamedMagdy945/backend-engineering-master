# Infrastructure Layer Structure

The Infrastructure Layer implements the technical capabilities required by the application, such as database access, file storage, email delivery, and integrations with external services.

It references the Application and Domain Layers to implement their required abstractions and persist domain data.

## Project Tree

```text
MyProject.Infrastructure/
│
├── Persistence/
│   ├── AppDbContext.cs
│   ├── Configurations/
│   │   └── ProductConfiguration.cs
│   ├── Migrations/
│   └── Repositories/
│       └── ProductRepository.cs
│
├── Services/
│   ├── Email/
│   │   └── EmailService.cs
│   └── FileStorage/
│       └── FileStorageService.cs
│
├── ExternalServices/
│   └── Payments/
│       └── PaymentGateway.cs
│
└── DependencyInjection.cs
```

## Folder Responsibilities

| Folder | Responsibility |
|---|---|
| `Persistence/` | Implements database access and persistence-related configuration. |
| `Persistence/Configurations/` | Contains EF Core entity configurations, such as table mappings and relationships. |
| `Persistence/Migrations/` | Contains database schema migrations generated by EF Core. |
| `Persistence/Repositories/` | Implements repository abstractions when the application actually needs repositories. |
| `Services/` | Implements technical services such as email delivery and file storage. |
| `ExternalServices/` | Integrates with external systems, APIs, and third-party providers. |
| `DependencyInjection.cs` | Registers infrastructure implementations and their dependencies. |

## Dependency Rules

- Infrastructure can reference Application and Domain.
- Infrastructure implements abstractions defined by Application when infrastructure capabilities are required.
- Infrastructure should not reference API.
- Application should not depend on Infrastructure implementations.
- The API or application composition root wires the required implementations into the application.

## Important Principles

- Keep EF Core and database-specific code in Infrastructure.
- Keep external API clients and their implementations out of Domain.
- Avoid creating repositories automatically for every entity. Use them when they provide meaningful value.
- Do not place business rules in persistence configurations or external service implementations.
- Keep connection strings, credentials, and other secrets in appropriate configuration providers rather than hardcoding them.

## Key Takeaway

The Infrastructure Layer defines **how technical capabilities are implemented**, keeping database and external-system details separate from application workflows and domain rules.
