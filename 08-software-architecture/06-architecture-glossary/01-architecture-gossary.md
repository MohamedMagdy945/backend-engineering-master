# Architecture Glossary

Quick reference for common software architecture terminology.

| Term | Meaning |
|---|---|
| Architecture | The high-level structure of a software system and its major design decisions. |
| Component | A part of a system with a specific responsibility. |
| Module | A unit of code organized around related responsibilities. |
| Coupling | The degree of dependency between components or modules. |
| Cohesion | How closely related the responsibilities within a module are. |
| Dependency | A relationship where one component relies on another. |
| Abstraction | Hiding implementation details behind a simpler interface. |
| Separation of Concerns | Dividing a system into parts with distinct responsibilities. |
| Modularity | Organizing a system into well-defined, manageable parts. |
| Scalability | The ability of a system to handle increasing workloads. |
| Maintainability | How easily a system can be understood, modified, and maintained. |
| Trade-off | A decision that improves one aspect while potentially sacrificing another. |
| Technical Debt | Future cost caused by choosing a quicker or less suitable technical solution. |
| Architectural Boundary | A defined separation that controls responsibilities and dependencies. |
| Architectural Drift | Gradual deviation from the intended architecture. |
| Monolith | An application built and deployed as a single unit. |
| Modular Monolith | A single deployable application with clearly separated modules. |
| Microservices | An architecture composed of independently deployable services. |
| CQRS | Separating operations that change data from operations that read data. |
| DDD | Domain-Driven Design: an approach that focuses software design on the business domain. |
| ADR | Architecture Decision Record: a document recording an important architectural decision and its reasoning. |
| Fitness Function | An automated check that verifies an architectural property or rule. |

## Key Takeaway

Use this glossary to quickly recall terminology. Refer to the relevant architecture document when you need a detailed explanation or practical examples.
